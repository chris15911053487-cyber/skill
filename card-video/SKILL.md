# 卡片信息视频

把一个主题或一篇文稿做成竖屏卡片动画视频。画面由 HTML 模板逐帧渲染（Playwright 截图 + ffmpeg 编码），文案全部在项目的 `content.js` 里，改文案重渲即可。

`SKILL_DIR` 指本文件所在目录。脚本都在 `SKILL_DIR/scripts/`。

## 总流程（每个 ☐ 是必须等用户确认的节点）

```
0 环境自检 → 1 选择模式 ☐ → 2 主题与文稿 ☐ → 3 补充需求 ☐ → 4 分镜预览图 ☐
→ 5 背景音乐试听 ☐ → 6 配音方案与试听 ☐（仅口播版） → 7 渲染、自检、交付
```

不要跳过确认节点一口气做完：模式、文稿、音乐、配音都是用户主观偏好，返工成本远高于先问一句。

## 0. 环境自检

```bash
bash SKILL_DIR/scripts/check_env.sh            # 只检查
bash SKILL_DIR/scripts/check_env.sh --install  # 自动装 playwright+chromium、edge-tts
```
需要 Node 18+、ffmpeg、python3、中文字体。缺什么就告诉用户怎么装（脚本会给出命令），装不了的项要说清楚影响（例如没 edge-tts 只影响 edge 配音）。

新电脑第一次用、或怀疑环境有问题时，跑一遍完整自检（约 30 秒，出一条 10 秒小视频并校验）：
```bash
bash SKILL_DIR/scripts/selftest.sh          # 加 --keep 保留测试成片
```

## 1. 选择模式 ☐

**动手写文稿前先问**，因为两种模式的文稿写法不同。用户请求里已经说清楚（如"做个口播视频""只要配乐"）就不用再问，在第 2 步展示文稿时顺带确认一句即可。有提问工具（如 AskUserQuestion）就用它给选项，否则用文字列出：

| 选项 | 效果 | 适合 | 时长 | 额外步骤 |
|---|---|---|---|---|
| **A. 纯音乐版** | 卡片按固定节奏逐张出现 + 背景音乐 + 翻页音效，无人声 | 信息一眼能看懂、静音刷也不丢信息、出片最快 | 每页 4~8 秒，整片约 35~50 秒 | 无 |
| **B. 口播版** | AI 配音讲解；讲到哪张卡哪张卡才出现，讲完自动换页；烧录字幕；背景音乐在说话时自动压低 | 需要解释的内容（概念、流程、对比）、想要"有人在讲"的感觉 | 由旁白决定，约 = 旁白总时长 + 每页 0.85 秒 | 第 6 步选配音方式、试听音色 |
| **C. 两版都要** | 同一套画面出两条：先做口播版，再用 `--music-only` 一条命令出纯音乐版 | 不同平台/场景分别投放 | 两条各自计算 | 同 B，多渲染一次 |

用户想用自己录的旁白、让卡片跟着他的录音出现：按口播版处理，见第 6 步"用户自录旁白"。

## 2. 主题与文稿 ☐

- **用户提供了文稿**：以用户文稿为准，只做"切分成页"的编排，不改写观点和数据；需要压缩字数时，把删改处列出来给用户确认。
- **用户只给了主题**：AI 创作文稿。结构建议（可按主题调整）：
  1. 钩子页：一句反常识/痛点/利益点大标题（≤12 字）+ 副标题
  2. 2~5 个内容页：每页一个观点，配数据、对比、步骤或清单
  3. 行动页：总结 / 活动权益 / 能带走什么
  4. 结尾页：回扣钩子 + 行动号召（或二维码）
- 每页屏幕字数要少：标题 ≤ 2 行，列表 ≤ 5 条、每条 ≤ 18 字。
- 数据和引用必须有来源；AI 不确定真实性的数字，不要编，改成定性描述或标注"示意"并提醒用户核实。
- 把文稿以"逐页"表格展示给用户，**等用户确认或修改后再继续**：
  - 纯音乐版：第几页 / 页面类型 / 屏幕文字 / 停留秒数
  - 口播版：第几页 / 页面类型 / 屏幕文字 / 旁白（带 `|`）

### 口播版文稿写法
- 旁白就是主线：先写一段连贯的讲解，再按讲解切页、配屏幕文字。屏幕文字是旁白的关键词提炼，不要照抄整句。
- 在旁白里用 `|` 标记"念到这里出下一张卡"：每页标题在页首自动出现，之后每个 `|` 依次揭示本页下一个揭示单元（顺序见 `reference/content-schema.md`）。`|` 的数量要等于揭示单元数。
- 旁白要短：每页 5~12 秒（约 25~60 字，语速 `--rate 8~15` 时）。用户给了目标时长时，按"目标时长 − 页数 × 0.85 秒"倒推旁白总字数（约 4.5 字/秒）。
- 每页 `dur` 设小（如 3），页长由配音决定。
- 旁白要好读：少用括号、符号和英文缩写（"≠"写成"不等于"，"Q3"写成"第三季度"）。

## 3. 补充需求 ☐

文稿确认后（或同时），一次性问清楚，并告诉用户这些都可以提供，不提供就用默认值：

| 项目 | 可以提供 | 默认 |
|---|---|---|
| 视频时长 | 目标秒数，如 30s / 60s | 纯音乐版约 35~50s；口播版由旁白决定 |
| 背景音乐 | 自己的音乐文件；或风格要求（科技/轻快/温暖/激昂…） | AI 按文稿风格去 sounddino 搜；保底 Technological Symphony |
| 配音（仅口播版） | 已录好的旁白；或 AI 配音偏好（男/女声、语速、风格） | AI 配音，edge-tts 男声 `zh-CN-YunxiNeural`、语速 +10% |
| 字幕（仅口播版） | 要不要烧录字幕 | 要 |
| 画幅 | 竖屏 9:16（抖音/视频号/小红书）或横屏 16:9（B 站/视频号横版/官网） | 竖屏 |
| 品牌 | 品牌名、logo 图片 | 占位品牌"你的品牌" |
| 配色 | 预设：紫 purple / 蓝 blue / 绿 green / 橙 orange / 深色 dark，或品牌色 | AI 按主题选（商务科技→蓝，健康财务→绿，零售活力→橙，发布会→深色） |
| 结尾 | 二维码图片、联系方式、行动号召语 | 回到钩子页 + 按钮文案 |
| 素材 | 产品截图、配图、表情/图标偏好 | 系统 emoji 作插画 |
| 发布平台 | 抖音 / 视频号 / 小红书 / B 站… | 抖音竖屏 9:16 |
| 脚注 | 免责声明、数据来源 | 通用免责声明 |
| 参考 | 喜欢的视频样例（可发视频文件，AI 抽帧分析） | 本技能默认风格 |

用户提供的文件放进项目目录的 `assets/`，在 `content.js` 里用相对路径引用。
画幅支持竖屏 1080×1920 和横屏 1920×1080（`format: '16:9'`，左栏标题右栏内容）；竖屏出片时自动附带 3:4 封面（小红书）。要方形 1:1 时，说明需要改模板版式，先确认再动手。

## 4. 建项目 → 写 content.js → 分镜预览图 ☐

```bash
bash SKILL_DIR/scripts/new_project.sh <项目目录>     # 例如 ./videos/2026-10-agent-camp
```
然后改 `<项目目录>/content.js`：页面类型和字段见 `reference/content-schema.md`（先读它）。`content.example.js` 是一个完整示例。
页面类型共 13 种：hero、list、grid、table、steps、cards、checklist、stats、timeline（时间线）、quote（金句/证言）、compare（左右对比）、image（截图，可局部放大）、outro（二维码）。按内容挑最合适的，连续几页不要用同一种。
文字特效（打字机、解密、流光、焦点跳词）已内置为 `<fx-*>` 标签，用法见 content-schema.md「文字特效」，适度点缀即可。还要别的特效时读 `reference/motion-recipes.md`，从 motion-anything 配方库移植（必须改写成 `seek(t)` 驱动）。
emoji 会自动换成 Fluent 3D 图标（任何系统外观一致）。按模式设置：

| | 纯音乐版 | 口播版 |
|---|---|---|
| `audio.voice` | `false` | 合成配音后改为 `true` |
| 每页 `voice` | 可不写 | 必写，带 `\|` |
| 每页 `dur` | 4~8（就是实际停留时长） | 3（最短时长，实际由配音决定） |

```bash
node SKILL_DIR/scripts/render.mjs <项目目录> --stills
```
- 输出 `preview/contact.png`（所有页关键帧拼图）和单页 png，并做**版面检查**：任何页面超出安全区会打印警告并以退出码 2 结束 → 删字、拆页或换页面类型，直到通过。
- 自己先看一遍拼图（文字溢出、换行难看、重叠），再把拼图给用户看（路径告诉用户，或在支持图片的界面里展示），**确认画面后再做音乐和配音**。也可以让用户用浏览器打开 `<项目目录>/index.html` 看实时动画预览。
- 口播版此时还没有配音，预览里的时长是 `dur` 的值，属正常；第 6 步合成后再预览一次。

## 5. 背景音乐 ☐

两种模式都需要背景音乐（口播版会在说话时自动压低）。来源按优先级：
1. **用户提供** → 复制到 `<项目目录>/music.mp3`（其他格式也行，改 `audio.music`）。
2. **AI 搜索下载**（用户没提供时）：根据文稿气质和用户要求，提炼 2~3 组英文关键词去 sounddino 搜：
   ```bash
   python3 SKILL_DIR/scripts/music.py search "corporate technology" --limit 8   # 每次 1~2 个英文词
   python3 SKILL_DIR/scripts/music.py download <序号> -o <项目目录>/music.mp3
   ```
   挑 2~3 首候选（说明各自风格、BPM、时长、为什么适合），每首都给出"在线试听"链接。口播版优先选旋律简单、没有人声、不抢话的曲子。
3. **保底**：搜不到合适的、网络不通或下载受限时：
   ```bash
   python3 SKILL_DIR/scripts/music.py fallback -o <项目目录>/music.mp3   # Technological Symphony（技能自带）
   ```
试听：`python3 SKILL_DIR/scripts/music.py clip <项目目录>/music.mp3 --start 0 --dur 20 --play`（本机直接播放 20 秒片段；远程环境就把文件路径或在线试听链接给用户）。**用户说可以再继续**。前奏太长可设 `audio.musicStart` 跳过。更多见 `reference/music.md`。

## 6. 配音（仅口播版）☐

纯音乐版跳过本步，直接到第 7 步。

- **用户自录旁白**：请用户照着 content.js 的旁白一口气念完录一段（手机录音即可，念错、停顿没关系），然后本地语音识别对齐，自动切页并算出每个 `|` 的时刻：
  ```bash
  python3 -m pip install --user faster-whisper        # 首次
  python3 SKILL_DIR/scripts/align.py <项目目录> --audio <录音文件>   # 首次会下载识别模型（约 480MB）
  ```
  输出"文稿与录音匹配 xx%"；低于 80% 时提醒用户录音和文稿差异较大。国内网络下载模型慢：先 `export HF_ENDPOINT=https://hf-mirror.com`。
- **AI 配音**：把三种方式的对比**原样展示给用户选**（表格与申请步骤见 `reference/tts.md`，展示时要包含：优势、劣势、需要用户提供什么、试听途径）：

  | 方式 | 优势 | 劣势 | 需要提供 |
  |---|---|---|---|
  | edge-tts | 完全免费、无需注册、装好即用 | 非官方接口，微软可能限流（403）或停用；音色较少、情感一般；商用授权不明确 | 无 |
  | 火山引擎（豆包语音） | 中文自然度高、音色多、可情感/方言/声音复刻 | 付费；新用户免费额度有限且有有效期；需实名开通 | API Key（或 App ID + Access Token） |
  | 腾讯云语音合成 | 免费资源包大、基础音色便宜、官方稳定 | 免费资源包领取后 3 个月过期、每账号一次；超额自动后付费 | SecretId + SecretKey |

  **合成前先查读法**：旁白里的英文缩写、产品名、符号（如 SAP、ERP、≠）可能读错。技能已内置常见读法（`assets/pronounce.json`）；文稿里有其他专有名词时，在 `content.js` 的 `audio.pronounce` 加上，例如 `{ 'SAP': 'S A P' }`（只改配音，不改屏幕和字幕）。

  用户选定后：先用第 1 页旁白合成样音给用户试听（可换音色、调语速），**满意后**再全量合成：
  ```bash
  python3 SKILL_DIR/scripts/tts.py voices --provider edge                          # 看音色
  python3 SKILL_DIR/scripts/tts.py sample --provider edge --voice zh-CN-YunxiNeural --rate 10 --text "<第1页旁白>" -o <项目目录>/voice_sample.mp3 --play
  python3 SKILL_DIR/scripts/tts.py build <项目目录> --provider edge --voice zh-CN-YunxiNeural --rate 10
  ```
  然后把 `content.js` 里 `audio.voice` 设为 `true`，再跑一次 `render.mjs --stills`：同时检查版面和口播揭示点（`|` 数量与卡片数不符会警告），并报告新的总时长。总时长明显超出用户预期时，先删减旁白再继续。
- **密钥安全**：密钥只写入 `~/.config/card-video/keys.env`（`chmod 600`），不要写进项目、文稿、聊天总结或任何会分享的文件。用户把 key 发给你时，代为写入该文件即可，回复里不要复述 key。
- edge-tts 报错（403 等）时，先 `python3 -m pip install -U edge-tts` 升级再重试。

## 7. 渲染、自检、交付

```bash
node SKILL_DIR/scripts/render.mjs <项目目录>                      # 输出 output.mp4 + cover.png（竖屏另有 cover-3x4.png）
node SKILL_DIR/scripts/render.mjs <项目目录> --out output-口播版.mp4  # 可自定输出名
node SKILL_DIR/scripts/render.mjs <项目目录> --music-only          # 纯音乐版：忽略配音、自动定页长 → output-音乐版.mp4
```
默认 4 路并行渲染（`--workers N` 调整），1 分钟视频约 1 分钟出片。
**两版都要（选项 C）**：口播版渲染完后直接加 `--music-only` 再跑一次，不用改文件。

交付前自检（都要做）：
- `ffprobe` 看时长、分辨率 1080×1920、有音轨；
- 抽几帧看画面（`ffmpeg -ss <秒> -i output.mp4 -frames:v 1 x.png`），确认转场、字幕位置正常；
- 口播版：从 `voice/manifest.js` 取两三个 cue 时刻，在 cue 前 0.2 秒和后 0.5 秒各抽一帧，确认卡片"之前没有、之后出现"；确认音乐被压低、人声清楚。

交付时告诉用户：模式、视频与封面路径、总时长、用了什么音乐（名称+来源）、配音方式与音色；如何改文案重渲；文稿里需要用户核实的数据。

## 修改迭代

- 改文字/顺序/时长 → 改 `content.js`，口播版改了旁白就重跑 `tts.py build`，再 `render.mjs --stills` 预览，最后全量渲染。
- 纯音乐版想改成口播版：补写每页 `voice`（带 `|`）、`dur` 改 3，从第 6 步继续。
- 改配色 → `content.js` 的 `theme`（预设名或颜色，见 schema）。
- 竖屏改横屏 → `format: '16:9'`，重新 `--stills` 检查（横屏高度小，可能要删条目）。
- 某个词配音读错 → 加到 `audio.pronounce`，重跑 `tts.py build`。
- 改动效/版式 → 改项目里的 `index.html`（只影响这个项目）；想让以后都生效再改 `SKILL_DIR/template/index.html`。

## 注意

- 不要冒用真实品牌的 logo 和名称做成"官方广告"的样子，除非用户就是该品牌方或明确有授权。
- sounddino 曲目可免费商用、无需署名（以其官网许可为准）；用户自带音乐的版权由用户负责，提醒一句即可。
- emoji 已自动换成 Fluent 3D 图标；图标库里没有的 emoji 仍是系统样式，可运行 `scripts/fetch_icons.py "<英文名>"` 补充，或让用户提供插画图片（`props[].img`）。
